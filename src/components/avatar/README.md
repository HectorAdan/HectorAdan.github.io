# Holographic avatar study

Open `?avatar=prototype` on the existing site. This separate, lazy-loaded preview does not replace the Neural Core or change portfolio navigation.

The temporary bust is original procedural geometry. It represents a generic head and shoulders, not Hector's likeness. There are no photographs, textures, talking animation, external model services, or new dependencies.

## Model boundary

`avatarSurface.ts` prepares either the procedural bust or a GLB as one normalized `BufferGeometry`. It bakes visible mesh transforms and the current skin/morph pose, combines surfaces, centers them, and normalizes their height to 3.8 scene units. `sampleAvatar.ts` samples that geometry with Three.js `MeshSurfaceSampler`. `HolographicAvatar.tsx` renders the same buffers for either source.

To use the future personalized model:

1. Export an **uncompressed, self-contained** head-and-shoulders GLB with Y up and the face looking toward +Z. Apply appropriate neutral pose, remove cameras/lights and hidden accessories, and keep geometry reasonably light (preferably below 50,000 triangles). Avoid a full body mesh; framing is designed for a bust.
2. Place the file at `public/hector-avatar.glb`.
3. Open `?avatar=prototype&model=hector`. The loader uses Vite's `BASE_URL`, including a GitHub Pages subdirectory if configured. If loading fails, the preview identifies the fallback and displays the temporary bust.

The source model's materials and textures are discarded after preparation; holographic shading is generated by the renderer. Draco/Meshopt compression requires extra decoder setup and is intentionally not enabled. No animation clips are played. Integrating the approved avatar into the main portfolio is a separate step.

## Rendering and accessibility

- 11,000 surface particles on desktop; 4,500 on compact/coarse-pointer devices. Three avatar draw calls (points, sparse pathways, translucent shell), plus two projector meshes. No bloom or post-processing passes.
- Spatial hashing builds local connections among a subset of particles; each has at most two connections, capped at 1,000 desktop / 430 compact edges. Energy travels along those segments using shader uniforms. The facial geometry does not animate.
- DPR is capped and can downshift once after warm-up on slow devices. Animation pauses in hidden tabs. OS reduced motion and the pause button use demand rendering; manual camera exploration still works.
- Front, three-quarter and profile buttons provide keyboard-accessible camera views. Dragging uses Three.js OrbitControls. WebGL errors and context loss show a route back to the working portfolio.
- Loader-owned surfaces, sampled buffers, source materials and textures, and controls are disposed when no longer needed.

The study is intentionally isolated for review. Further anatomical refinement and a real personalized model will improve identity and expression without changing the particle renderer.

## Private MediaPipe mask review

Open `?avatar=prototype&model=mediapipe`, choose **Load facial mask**, and select the private `avatar-references/mediapipe-poc/output/hector-mediapipe-poc.glb` file. The browser reads this self-contained GLB through a temporary object URL; it is never uploaded or copied to `public/`. This mode loads only the chosen facial mask and never creates a fallback bust. It uses the unchanged `HolographicAvatar` particles, Plexus pathways, shell and projector. The three-quarter camera is 45 degrees for comparing facial depth. The default prototype and `model=hector` mode are preserved.

The mask contains inferred depth and open eyes/mouth, with no reconstructed skull, hair, neck or shoulders. Keep the generated GLB and reference photographs inside the ignored folder. This is a likeness evaluation, not an animation-ready personalized avatar.

## Portfolio introduction

The home page's **Meet Hector** action uses `canvas/NeuralIdentity.tsx` to hand off the original Neural Core to the existing holographic renderer. The public model at `models/hector-mediapipe-poc.glb` matches the private proof-of-concept GLB; no photograph or skin texture is embedded. It loads through Vite's `BASE_URL`. To upgrade later, change `IDENTITY_MODEL_PATH` to another self-contained neutral GLB with Y up and +Z facing forward. `avatarSurface.ts` still provides the common normalization boundary.

`utils/identityIntroduction.ts` describes the activation, Core fade, facial reveal and particle assembly timing. Core activation starts immediately; the camera approaches over about 1.1 seconds. From 1.1 to 3.3 seconds, a separate cloud converges onto the sampled facial surface while the Core recedes. This is a staged transition, not a deformation of the Core's original points. Closing restores the original presentation; replay restarts both particle and text reveals. The face stays mostly front-facing with a few degrees of idle tilt and cursor response. There is no orbit control, talking animation, voice or facial reconstruction.

The introductory surface layer is 16% of the isolated study's shell opacity, keeping particles as the primary structure. A sparse atmospheric point layer softens the incomplete perimeter without creating skull, hair, neck or shoulders. The original isolated preview keeps its default shell, projector and camera controls.

Performance: 11,000 face particles / at most 1,000 pathways on desktop; 4,500 / at most 430 on compact devices. Atmosphere adds 180 / 72 points. Four identity draw calls and no post-processing; Core and face overlap briefly during the handoff. Geometry is sampled once per source/quality change; animation uses refs and uniforms, with no per-frame React state updates. Hidden tabs stop rendering. Reduced motion skips camera travel, particle assembly and idle motion, and reveals the text immediately. The same 4,500-point surface is used on mobile with face-above-text framing and a scrollable text area on short screens.

If the GLB fails to load, the Core remains available and the text introduction still works. If WebGL is unavailable, the existing lightweight environment carries the introduction and all portfolio navigation. The model remains a coarse single-photo facial mask with empty eyes/mouth and no side anatomy. Holographic presentation does not correct its depth or guarantee a strong likeness.

Checks: `npm run build`, `node scripts/check-avatar.mjs`, and `node scripts/check-identity.mjs`. Browser checks cover Meet Hector, replay, closing/Escape, navigation after introduction, production asset loading, mobile framing, reduced motion and missing-model/WebGL fallback.

Run `node scripts/check-avatar.mjs` to validate geometry bounds, normalized normals, deterministic sampling, local connection lengths and degree caps, and preparation of transformed mixed meshes. `npm run build` validates TypeScript and the static production build.
